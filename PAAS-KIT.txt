PAAS-KIT  -  separate from the storage brain update
====================================================
File: paas-kit-c2dc8a2.zip   (528M)   SHA-256: 1fdecf02caf508f8119eb11a75e42acad4ca3afb6c6e88e213728a6a93ac7f73

A separate zip, not part of the brain. Install it once as root: every user on the VM, and every user created later,
has all of it on, whatever brain (team) they use - no question asked, and users cannot turn it off. Only root can
(below). It never changes the brain, a team repository, managed-settings.json or anyone's own settings.

  rtk                 shorter shell output, with rtk's own hook as rtk ships it: every command rtk knows (git, ls, cat,
                      grep, find, tests, builds, oc / kubectl / docker, curl ...) runs in its short form. The model
                      types plain commands. Only check: the model may not type "rtk ..." itself (the brain's guard
                      cannot see inside it). 18 ms per command, the same as rtk anywhere. Left as typed: oc, kubectl,
                      grep, egrep, rg (rtk hid failing pods and log errors in testing; paas-kit rtk exclude ... changes it).
  Headroom            makes the model's input smaller. Default profile safe, strictly lossless: JSON lists become
                      compact tables, every row and value kept (measured: volume list 70%, host list 53%, port list
                      68% fewer tokens). Logs and documents reach GLM unchanged. profile full adds Headroom's other
                      compressors and Kompress (included, offline). If it stops, sessions go straight to GLM.
  MEASURED TOGETHER   one session of 8 shell commands + 4 MCP results: 96,263 tokens plain -> 88,984 with rtk (8%)
                      -> 43,878 with rtk + Headroom safe (54% fewer), nothing left out except what rtk prints a
                      "rtk recall <hash>" for.
  code-graph plugin   for large code bases: a graph of the git repository the model asks instead of reading files
                      (what a change breaks, who calls what, review). /code-graph:build once per repository.
  fastapi-api plugin  Python REST APIs offline: /fastapi-api:new <name>, paas-kit venv, rules, api-reviewer agent.
  ast-grep            structural code search on the PATH.
  Not included: Go (dropped on request).

INSTALL  (on the VM, as root; needs python3.12:  dnf install -y python3.12; ~2 GB free in /opt)
  cd /root && cp /path/to/test_temp/paas-kit-c2dc8a2.zip .        # the folder you git-pulled
  sha256sum paas-kit-c2dc8a2.zip                               # must print 1fdecf02caf508f8119eb11a75e42acad4ca3afb6c6e88e213728a6a93ac7f73
  unzip -q -o paas-kit-c2dc8a2.zip
  sh paas-kit/install.sh
     -> at the end "model ... <your GLM address>" and "new sessions  through Headroom".
     -> "model address: NOT FOUND": run it again with your address:
        sh paas-kit/install.sh --upstream https://<the GLM address Claude uses today>
  paas-kit status
  Then start a new chat in the web UI (running chats keep the old setting until restarted).

CHECK THAT IT WORKS
  in a new chat (auto mode): "run git log -5 --stat and ls -la"   the output comes back in rtk's compact form;
                                       after a while: paas-kit gain   (each user's rtk savings)
  paas-kit status                      Headroom "answering", "new sessions through Headroom", savings after some use
  in a new chat inside a git repo:     /code-graph:build      then ask "who calls <function>?"
  journalctl -u paas-headroom -n 50    the Headroom log

TURN THINGS OFF / REMOVE (root)
  paas-kit headroom off                sessions straight to GLM again (on: paas-kit headroom on)
  paas-kit plugin off rtk              a plugin off for everyone (also code-graph, fastapi-api); on: plugin on
  paas-kit headroom profile full       Headroom: every compressor + Kompress (back: profile safe, the default)
  sh /opt/paas-kit/kit/uninstall.sh    removes everything the kit added

FROM AN EARLIER paas-kit (any version)
  the same steps; settings are kept. This one: rtk with its own hook, Headroom with its own defaults + Kompress
  This version: Headroom safe never drops rows (it did on Harvest / Prometheus results), and rtk leaves oc, kubectl
  and grep as typed. Headroom in token mode, profile safe unless root chose full.

UPDATE LATER
  unzip the new zip and run  sh paas-kit/install.sh  again (its settings are kept).
