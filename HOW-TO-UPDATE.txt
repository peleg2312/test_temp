2. Copy both to the VM (/root), then as root:
     cd /root && unzip -o storage-brain-update-0947709.zip
     sh update-2b433c1-0947709/apply-update.sh /path/to/storage-mcp-servers
     cd /path/to/storage-mcp-servers && sh brain/multiuser/install-multiuser.sh --docs-port 8443 --plain-http
     (both flags once, remembered after that:
      --docs-port 8443: the docs service moves to 8443, firewalld opens 8443 and closes 8001
      --plain-http: the docs MCP service (8443) and the marketplace for other VMs (3443) answer http:// instead of
        https://; the token is still required, but nothing is encrypted on the network (the docs token and the teams'
        notes could be read by someone capturing traffic). The sign-in page stays HTTPS. --https goes back.
      Every team plugin's docs-http and the Market's docs items get the new http://<vm>:8443 address in the same run.)
     systemctl restart 'paas-ui@*'
3. The library (as root):
     cd /root && unzip -o flashback-library-2026.11.04.zip
     /opt/paas/bin/paas-library import flashback /root/flashback-library-2026.11.04.tar.gz
     /opt/paas/bin/paas-library list                   -> flashback  31356 documents  218 MB ...   (about 30 s)

What was tested here, on clean machines with the real Claude CLI (docs service on plain HTTP 8443, a git-served team repo):
  - machine A: only the two plugin commands -> docs-http Connected (no certificate), docs-local Connected
  - first session: the team set up (knowledge clone, links, rules)
  - a note written on A -> committed as A's person, pushed to the team repository, indexed by the VM's docs service
    and found over docs-http (first in the results)
  - machine B: the two commands + first session -> it has A's note
  - an admin edit of the team (a Commvault server) -> machine A's next session start installs the new plugin in the
    background; active from the session after
  - the marketplace for other VMs over http: snapshot with the token, 401 without, paas-market connect http:// works
