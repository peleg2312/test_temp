New in 5d5a69f: brains of any shape, and nothing overwritten
  Shapes that now work as they are (nothing in their repository changes):
  - a marketplace with several plugins: all of them are switched on and off together
  - a plugin folder (like redbull-brain): as before
  - a "project-style" brain: CLAUDE.md + .claude/skills, .claude/agents, .claude/commands (+ its .claude/settings.json
    hooks and .mcp.json servers): becomes a plugin from its .claude folder; its CLAUDE.md is read in every chat as its rules
  - only skills/ / agents/ / commands/ at the top, or only a CLAUDE.md
  - knowledge under any folder name (wiki/, kb/ ...): found by content; docs for the library: docs/upstream
  Anything else, root says it WITHOUT touching their repository, in a file beside the VM copy:
      /opt/paas/teams/<name>.brain.json     e.g.  {"docs": "manuals", "knowledge": {"folders": ["wiki"]}, "rules": "GUIDE.md"}
  (then:  /opt/paas/bin/paas-team docs <name> --force     for the library now; members: switch again for the rest)
  Never overwritten:
  - their repository (missing plugin files are written into the clone only, untracked and git-excluded); the VM copy is
    only fast-forwarded to its git, and NOT pulled when root changed something in it by hand
  - your own: a settings.json env value with the same name as the brain's comes back when you leave the brain; so does a
    docs-local you had, and (outside the VM) your persona.md; your other plugins are not touched
  - libraries: a brain's docs only go into its own library; a brain.json naming an existing library (e.g. flashback) is refused
  - the VM: this update adds the paas-brain-docs service + daily timer and the current docs server files in
    /opt/paas/library; docs port, http/https, the docs token, firewall, team repositories and accounts' edits stay as they are

  - Docs service (docs-http, port 8443): indexes its knowledge pages (knowledge/, runbooks/, incidents/, notes/ ... or

  - docs-local: whoever switches to it (Brain tab -> Team -> redbull) gets a docs-local that searches its library together

New in bf145dd: each team's git is the boss (the installer no longer changes teams)
  - Hooks and the read-only guard of a team come from its git repository. With a team chosen (Brain tab), the VM's own
    copies step aside and the team plugin's hooks run, exactly what its git holds: remove a hook or the guard there and it
    is not run for that team; nothing on the VM puts it back. "No team" sessions keep the VM's default hooks and guard.
    The VM still protects its own secrets (the API key in /etc/paas) and its hook files.
  - install-multiuser.sh / install-shared.sh never change a team repository again (not on the VM, not in GitLab):
      a team already on the VM is left as it is; a GitLab project with content is left as it is;
      only a team that does not exist yet is built, and an EMPTY GitLab project gets its team's first content once.
  - --team <name>=<git url> works for any team or brain: one already here only gets its url recorded; one of brain/teams
    that is not here is built once; any other repository (a team built elsewhere, an external brain) is cloned as it is.
  - Updating a team from this repository is now your decision, one command, when you want it:
      python3 brain/teams/publish.py <team> --to <its GitLab url>     (it refuses to drop the team's own edits; --force does)
  - Note: a change of the docs port or http/https no longer rewrites the teams' docs address; change it in the team's git
    (Brain tab -> Team -> More -> Edit a team -> docs-search).
